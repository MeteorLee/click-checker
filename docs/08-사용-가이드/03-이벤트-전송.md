# 이벤트 전송

## 목적

- `POST /api/events` 요청에 무엇을 넣어야 하는지 정리한다.
- 필수값, 자주 쓰는 값, 성공 기준을 빠르게 확인할 수 있게 한다.

---

## 1. 요청 경로

- `POST https://clickchecker.dev/api/events`

헤더:

```text
Content-Type: application/json
X-API-Key: <API_KEY>
```

---

## 2. 가장 짧은 예시

```bash
curl -X POST https://clickchecker.dev/api/events \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <API_KEY>" \
  -d '{
    "eventType": "page_view",
    "path": "/",
    "occurredAt": "2026-03-29T12:00:00Z"
  }'
```

성공하면:
- `200`
- 응답에 `id`

---

## 3. 자주 넣는 필드

### `eventType`
- 원본 이벤트 이름
- 예:
  - `page_view`
  - `product_view`
  - `add_to_cart`
  - `purchase_complete`

### `path`
- 사용자가 본 경로 또는 행동 경로
- 이후 route key 정규화 기준이 될 수 있다.

### `occurredAt`
- 이벤트 발생 시각
- ISO-8601 UTC 문자열 권장

### `externalUserId`
- 식별 사용자 키
- 있으면 식별 사용자 이벤트
- 없으면 익명 이벤트

### `payload`
- 추가 메타데이터
- 예:
  - `source`
  - `campaign`
  - `device`

---

## 4. 권장 예시

```bash
curl -X POST https://clickchecker.dev/api/events \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <API_KEY>" \
  -d '{
    "eventType": "purchase_complete",
    "path": "/checkout",
    "externalUserId": "user-101",
    "occurredAt": "2026-03-29T12:00:00Z",
    "payload": {
      "source": "web",
      "campaign": "spring-sale"
    }
  }'
```
